## Completed foundations in this source snapshot

- Node.js modular core, PostgreSQL source of truth, Memgraph graph projection, versioned transactional outbox.
- EnginEx 7.0.0 safe rendering adapter (legacy JavaScript template execution removed) and versioned page-document model.
- AI provider adapters, content/page drafting, schema validation and constrained MCP tools.
- Identity/session and publication workflow foundations; browser editor baseline.
- File/Document/Media libraries, curated icons, video widgets, math formula validation/rendering, optional optimization.
- Product/order/membership domain foundations; 0.5.1 adds finite-stock reservation lifecycle helpers, provider-aware reconciliation of expired Stripe Checkout Sessions, and ambiguous create-session recovery with exact request snapshots. It fails closed and retains holds when the session ID/provider state is unknown. Live Stripe/DB tests remain gated.
- 0.5.1 adds partial site-scoped direct-conversation/message, notifications/read markers, blocks, reports and moderation routes with rate limiting; group privacy, forums, export/deletion and full browser workflows remain open.
- Release-readiness tooling records syntax/unit/vendor/integration results separately from required deployment evidence and produces a fail-closed gate report.
- F1.7 completes a documented CRDT-versus-semantic-OT assessment for the current page-document/editor model and records a provisional server-authoritative OT direction in ADR-019; implementation remains a separate milestone.
- Optional ClamAV scanner adapter, fail-closed production upload policy, non-production quarantine, local disk object reconciliation tool.
- Read-only cloud-storage probe methods (live provider operations require provider credentials and were not tested here).
- PostgreSQL outbox concurrency/dead-letter test definition, Memgraph monotonic projection integration test, and CI definitions for supported Node, database services, Playwright and CodeQL.

## Release policy

The CI workflow is a test definition, not evidence that a job passed. Each milestone needs retained acceptance logs/results. Capability files, UI surfaces and database tables alone do not imply user-facing parity. VirgoScorpio Hub must not claim production certification until all release-gate requirements are satisfied.

## Addendum — 9 November 2026 (F1.19 Redis reconnect resilience)

F1.19 fixes the Redis real-time bridge's finite reconnect cutoff. Publisher and subscriber clients now share one bounded exponential equal-jitter reconnect strategy: a 100 ms initial window, exponential growth, a 5-second cap, and a returned delay between 50% and 100% of the current window. Reconnect attempts continue until explicit bridge shutdown; the existing fixed-cardinality `redis_reconnect_attempts_total` counter records each strategy invocation. Tests inject a deterministic random source without changing the production default.

The regression suite covers retry counts 0, 1, 2, 5, 10, 11 and 64 at both jitter bounds; shared publisher/subscriber policy; metrics; and explicit shutdown. Focused Redis tests passed **11/11**. The full `npm run check` passed **567 tests: 564 passed, 0 failed, 3 Windows-specific skips**, with 230 required paths and 236 JavaScript files syntax-checked. These checks validate the policy and repository contracts, not an actual prolonged Redis outage or Redis Cluster/failover/network-partition behavior.

Redis Pub/Sub remains ephemeral and does not replay notifications missed during a disconnect. ## Addendum — 9 November 2026 (F1.20 Redis outage/recovery qualification)

F1.20 carries the reconnect resilience work beyond deterministic retry-policy tests. The policy is extracted once and reused for both bridge publisher/subscriber clients and the Redis-backed presence client. Both Redis client paths disable offline command queues. Bridge Pub/Sub sends fail fast while the publisher is not ready, preserving same-instance local-first delivery but not queueing ephemeral remote notifications; Redis presence reads/writes fail closed while the client is not ready, avoiding stale lease commands being replayed after a reconnect.

A CI-only integration test is added for a real Redis stop/start cycle. It requires a credential-free loopback Redis URL and the exact full container ID of the one approved running `redis:7.4-alpine` service. The test validates container identity/image/state before fault injection, waits for publisher/subscriber and presence reconnect attempts to exceed the previous ten-retry cutoff, verifies readiness/degraded metric recovery, ensures outage-time Pub/Sub notifications are not replayed, and checks refreshed site-scoped presence snapshots. A companion PostgreSQL-backed browser scenario revokes membership while the same physical Redis outage is active; the remote idle WebSocket must close through the existing PostgreSQL heartbeat reauthorization fallback and no revoked collaborative operation may be committed. The test restores the exact container in `finally`, while CI also has an `if: always()` service recovery step. Both safety gates are scoped to this dedicated disposable service; no developer/shared/remote Redis endpoint is stopped or mutated.

Current local evidence: focused deterministic tests report **28 passed, 0 failed, 1 intentionally skipped** (the actual outage test is gated to hosted CI); syntax checks passed for the integration/container helpers, browser test and runner; the tenant-isolation inventory regenerated with **27 families, 78 route patterns, 19 implementation files, 41 test files**. Hosted PR run `42578629207` and push run `42578566633` both passed the live Redis stop/start case with 11–12 bridge reconnect attempts, 11 presence reconnect attempts, successful post-recovery relay, no Pub/Sub replay and refreshed site-scoped presence. The companion browser heartbeat-authorization case timed out at 120 seconds in both runs; the `if: always()` Redis restoration step passed. A diagnostic retry adds stage markers, request timeout, post-start Redis PING and Playwright artifact upload. F1.20 remains **PARTIAL / NOT ACCEPTED** until the PostgreSQL heartbeat revocation fallback passes. The deterministic test suite alone does not prove live Redis recovery.
