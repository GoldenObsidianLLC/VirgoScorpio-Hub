## F1.35 — Plugin registry lifecycle/audit atomicity (merged; issue #156 CLOSED; PR #157)

### Source gap and implementation

Mainline commit `233f8e9cf61f391cb46d269c2dd3f87ff75d1023` includes F1.35, merged through [PR #157](https://github.com/GoldenObsidianLLC/VirgoScorpio-Hub/pull/157) on 15 November 2026. [Issue #156](https://github.com/GoldenObsidianLLC/VirgoScorpio-Hub/issues/156) is CLOSED.

The source gap was five plugin registry mutation paths where registry state was committed before the correlated audit write: registration/upsert plus `plugin.registered`, and approve, security-review, activate and disable plus their `plugin.<action>` events. Lifecycle state was also read without a row lock before validation, allowing a concurrent re-registration to clear approval/review state while a second-administrator review used stale values.

F1.35 reuses the existing `withTransaction(localPool, work)` and `identity.audit(input, { queryable })` seams. Registration/upsert and all four administrative transitions now persist state and correlated audit in one PostgreSQL transaction. Lifecycle validation obtains the site-scoped plugin row with `SELECT ... FOR UPDATE` through the active transaction queryable before checking status, approver/reviewer separation, signature/artifact/SBOM provenance and pinned-image requirements. External `invoke` and sandbox execution stay outside transaction/row-lock scope. No parallel transaction abstraction, schema, migration, dependency, public route, API contract, lockfile or package-version change was introduced.

### Regression coverage and hosted evidence

The existing two-site PostgreSQL fixture injects `audit_events` trigger failures for registration and every administrative transition. Each injected failure verifies rollback/no correlated audit, followed by retry/exactly one audit record. A deterministic advisory-gated concurrency regression pauses replacement registration in its audit transaction, queues security review behind the site-scoped row lock, then verifies the reviewer reads the replacement pending row and is rejected. The fixture restores the expected disabled state after this test.
